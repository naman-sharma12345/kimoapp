# Phase 0 decisions

The supplied PDF is the product specification. Its implementation rules govern this repository's work; it is not authority to access unrelated projects or services.

1. **Empty workspace and repository.** Build the monorepo directly in this checkout and push to the user's existing `naman-sharma12345/kimoapp` repository. No engine or backend repository is accessed.
2. **Phase boundary.** `/` redirects to `/dev/tokens`. Future route and component directories contain `.gitkeep` files rather than product screens. Error and not-found boundaries use existing tokens.
3. **Resolved versions.** Use pnpm 9.15.9, Next.js 15.5.28 and React/React DOM 19.1.10 within the requested major versions. The lockfile pins all resolutions. TypeScript 5.9 satisfies 5.6+. Retain ESLint 9 because the specification explicitly requires it. Use Node 22+ for native TypeScript execution, avoiding an extra runner dependency. `ws` and its types are the explicitly permitted server-only WebSocket implementation.
4. **Token aliases.** Preserve every named primitive inside `@theme static`; add Tailwind v4 `--color-*`, `--text-*`, and `--radius-*` aliases so utilities such as `bg-ink-1`, `text-cream-60`, and `rounded-r12` work. Token aliases introduce no new visual values. Typography includes all size, leading, tracking and weight values. Numbers use tabular numerals globally.
5. **Diagnostic specimens.** The token page must show every orange value together; these are labelled reference swatches, not product actions or decoration. Radius-pill and Instrument Serif are displayed as diagnostic specimens only. Their product restrictions remain intact. Passive dark control-height specimens avoid implying interactive buttons without actions.
6. **Unspecified preview layout.** Use existing 64px desktop / 20px mobile page gutters, 24px specimen gaps, 40px section gaps, 28px page title, 15px section titles, 12px metadata, 8px swatch radius and cream-60 readable labels. The 1440px content cap and 640px responsive breakpoint are structural measurements, not new design tokens. The exact quoted pangram is kept in source; uppercase label styling applies to the t-11 specimen.
7. **Motion.** Durations in motion.ts use seconds, exactly matching CSS milliseconds. Every translate/scale preset has an opacity-only 140ms reduced variant. Motion demos remain still until replay is requested, and contain no loops. Easing `ease-in` is demonstrated only as an explicitly labelled curve specimen; product usage is exits only. Springs are exported exactly and documented, without adding spring product interactions in Phase 0.
8. **Undefined contract members.** TextStyleId is a nonempty backend-owned string. Effect is `{id,type,params}` with unknown-valued parameter records. Keyframe is `{id,property,time,value,easing}`; numeric values only in this foundation. Marker is `{id,time,label}`. Transition is `{type,duration}`. These choices are documented proposals for backend agreement, not claims about an existing engine API. `clip.update` and `track.update` accept shallow partial patches excluding immutable IDs; nested values are complete replacements.
9. **Time and geometry.** All timeline/source time is seconds; rotation is degrees; opacity/crop are 0..1; normalized SAM polygons use 0..1. `clip.trim.value` is an absolute source in/out boundary, transformed by clip speed. Splits use absolute timeline time. Support 1920×1080, 1080×1920 and 1080×1080 to make the required 1:1 aspect usable; square is an explicit extension to the dimensions enumerated in the PDF. Operations are atomic and reject unknown references, duplicate IDs and invalid timing. Project duration is recalculated from clips after edits.
10. **Synchronization.** The shared client serializes remote batches and optimistic edits. Older/duplicate batches are ignored; a version gap or a newer hello triggers a snapshot refetch. HTTP 409 rolls back to a fresh snapshot, re-applies the user's ops once, and retries at that baseVersion. A second conflict/error restores the latest snapshot and is surfaced to the caller. This prevents an unbounded retry loop.
11. **Mock data.** Five requested primary assets plus mask/delivery support files are bundled and verified in postinstall; missing files download from the per-file manifest URLs. The original geometric clips and synthesized music are CC0. **Source substitution:** use original reproducible CC0 media rather than unverified Pexels/Pixabay stock URLs. Their current licenses cannot be assumed CC0. See fixture SOURCES.md for links and licensing evidence. This differs from the requested stock-provider source, while preserving five usable assets, duration/resolution, attribution and network-free fresh clones. The mock delivery is a playable canned video; the mock does not render edited project state.
12. **Mock limits.** Plain Node HTTP + ws, localhost only, 100 MiB per mock upload, 1 MiB JSON bodies, 15-minute upload expiration, CORS/preflight and media byte ranges. Session state is in memory; uploaded bytes persist to `.mock-data`. The script begins on the first WebSocket subscription so accelerated demos cannot miss the opening events; reconnects retain the same session clock. Script time pauses, resumes and scales with MOCK_SPEED. Script actions whose target was removed by a user report an action failure and continue instead of crashing the server. Warmup is 6s, then 45 actions over 70s; approval advances a 25s render clock. GET render materializes completion, matching the polling contract. Interrupt acknowledgement is immediate and followed by 3–4 edits. Slower/longer requests adjust pacing, music/quiet/loud requests change gain, other notes refine framing (or add note markers before clips exist). Semantic natural-language understanding belongs to the real backend.
13. **Fonts and mark.** Geist comes from its package. Instrument Serif italic 400 and its OFL license are vendored from the Google Fonts repository, loaded with next/font/local to avoid build-time network fetches. Font utility overrides put Next's generated font-face names before the exact specified family fallback tokens; this prevents Tailwind's utility layer from falling back to a system serif or monospace. The mark's four 3px bars start at x=2.5, 8, 13.5 and 19, so the required x=15 playhead crosses the third bar. The top triangle is 4px wide. It appears only as the favicon in Phase 0.
14. **Screenshots.** Use full-page screenshots with the requested viewport sizes so every token is evidenced, and emulate reduced motion for deterministic captures. Capture readiness waits for client hydration, font readiness and the next painted frame. Each later studio route automatically gains a 1920×1080 capture when `studio: true` is registered.
15. **Skills.** Skills are installed into the user's Codex skill directory with the official installer helper, using the actual upstream paths/names. This is equivalent to selecting Codex in the PDF's interactive skills CLI, without hanging on prompts. No skill can change the specified visual language or authorize unrelated actions. See SKILLS.md and skill-installation.json for the actual inventory.

5. **Motion and loops.** Shared active backgrounds/underlines use per-instance layout IDs and the exact snappy spring. Switch knobs use the same spring. Toast entrance uses soft. Reduced motion disables shared position interpolation, leaves loops static, and uses short opacity entry while retaining the correct final state. A gallery pause/resume control also freezes nonessential demonstration loops for users who have not enabled reduced motion. The skeleton uses a translucent solid 40%-wide band rather than adding an unauthorized gradient.
6. **Toast limits and timing.** Oldest eviction is immediate when a fourth notification arrives, enforcing at most three mounted notifications rather than retaining a fourth during an exit animation. Normal dismissal is also immediate; entry/stack motion follows the supplied presets. Hover, keyboard focus and hidden-tab state pause remaining time. Errors use an assertive live region; other notifications use polite status announcements. Static gallery toast specimens omit onDismiss so they remain available for inspection; provider-driven toasts use the exact 4s/8s lifecycle.
7. **Attachment anatomy.** The specified 40px outer height, 4px padding and 32px thumbnail are retained with centered alignment inside a 1px border box. The media poster is the original CC0 still from Phase 0, copied into public/dev so the component gallery works without the mock server. 8. **Reference logo.** Save the user's supplied 50×51 PNG unchanged as docs/brand/kimo-reference.png. It is a brand reference, not a request to replace the explicit Phase 0 vector geometry. Phase 1's agent avatar placement is the named exception to Phase 0's mark placement list. Do not upscale the raster or put its baked-in orange detail inside an avatar that already has an orange acting ring.
9. **Skill scope.** Read design-system-patterns, vercel-composition-patterns, emil-design-eng, accessibility-compliance, impeccable and web-design-guidelines. Impeccable context loaded the existing design bible; its missing-PRODUCT interview/concept flow is unnecessary for this precisely specified component extension. No new design direction is proposed. Review findings are resolved in this implementation or explicitly recorded here; optional style preferences never override the phase's fixed visual values.

## Phase 3 decisions and Phase 2 polish

1. **Shared lifetime.** A root-layout upload provider owns connectivity, refresh warnings and restoration. The singleton Zustand-backed manager keeps three files active, picks the smallest queued file first, and limits each multipart file to four active parts. Removing a chip cancels its requests and removes it from the saved session.
2. **Multipart contract.** MB/GB limits use binary units, consistent with Phase 2. Files above 100 MiB receive 16 MiB part URLs. The client sends ordered part numbers and ETags to POST `/v1/uploads/:id/complete`; POST `/v1/uploads/:id/renew` retains the asset ID when a signed URL expires. The mock streams parts to disk, validates their lengths and ETags, assembles them, and serves ranges without reading whole uploaded files into memory. This replaces Phase 0's 100 MiB mock cap with the 2 GiB product limit.
3. **Cancellation after navigation.** POST `/v1/sessions/:id/assets/remove` detaches canceled assets, so the backend does not wait forever for a canceled upload. This small contract extension is required for meaningful cancellation after session creation. The real backend must adopt the same semantics.
4. **Browser preparation.** Image resizing and waveform reduction run in a Web Worker when supported. DOM video metadata/seeking and OfflineAudioContext decoding stay on the main thread because those APIs are not generally available in workers. Filmstrips and waveforms start after uploads start. The ten-minute decoding limit bounds local audio memory; unsupported media still uploads and uses the required placeholder.
5. **Persistence.** IndexedDB holds original Files, thumbnail/filmstrip blobs, peaks, completed multipart parts and signed targets. Blob URLs are recreated after refresh and revoked on removal. SessionStorage holds the session ID, exact untrimmed prompt, attachment descriptors and local-to-asset map. Storage failures show a warning; quota or privacy restrictions can prevent durable local-file recovery, so the user is told to keep the tab open.
6. **Session routes.** Studio deep links fetch the typed snapshot and redirect according to status. Snapshots now optionally include renderId/videoId. Unknown sessions use the exact Phase 3 not-found copy, and shared errors use its exact upload/session variants. Studio, render and delivery routes contain only the minimum handoff needed by these redirects; later phase scenes remain unimplemented. The mock expires session lookups after 24 hours, but still loses all in-memory session records on process restart.
7. **Chip readability.** Retain Phase 1's cream-60 metadata contrast correction for readable waiting/reading/error text, rather than reproducing cream-38's measured contrast failure. The decorative unsupported-video icon uses the specified cream-38. All new dimensions, colors, fades and error borders use existing tokens or explicitly specified Phase 3 values.
8. **Phase 2 polish.** Replace approximate composer and attachment CSS easing with the exact soft/snappy springs, retain the user's requested absence of an inner textarea outline, improve bottom-bar layout, preserve the raw prompt, and move upload ownership out of the composer. The metadata base now resolves social images against app.getkimo.tech. The original placeholder step images and fixed visual language remain as specified.
9. **Verification.** Limit Vitest to two workers to keep simultaneous browser and media tests within local memory. A generated sparse 150 MiB text file exercises real multipart traffic without wasting disk space. The test mock can run with accelerated time for redirect checks; production-facing timing and visual tokens are unchanged.

## 2026-10-28 · sign-in, security and privacy pass

- Sign-in offers every provider `/v1/auth/providers` reports (GitHub and Google). The first (GitHub) is the one orange primary button, Google uses `kimo-btn-secondary`, so the one-orange rule holds. Entry points that only route to /signin now read "sign in" instead of naming one provider.
- Callback errors are specific (`cancelled`, `expired`, `not_allowed`, `unavailable`, `rate_limited`) with the provider in the URL; `popup_closed`/`network` stay for the client side.
- Legal and secondary text on dark uses `--cream-60` (about 6.7:1) instead of `--cream-38` (3.2:1) to meet WCAG AA.
- App security headers come from `next.config.ts` (`src/lib/security-headers.ts`); `deploy/_headers` is only for the old Pages build.
- Bring your own AI key (Oct 28 2026): the studio's "ai settings" popover (key icon in the agent panel header) reuses `.editor-field` inputs and the existing popover; its notes use `--cream-60` / `--t-11` and errors `--warning`, so no new tokens. The key lives only in React state for the open tab (never storage, cookies or the server's records); only the provider and model id are kept in localStorage (`kimo.ai.choice.v1`). The key travels per request in the `X-AI-Key` header to the Worker, which forwards it to the chosen provider and drops it. With a user key, interrupts go over HTTPS instead of the realtime socket so the socket never carries the key.
